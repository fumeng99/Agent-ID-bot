# 设计说明

本文记录 Agent ID Bot 的架构取舍、各层职责，以及在实际运行中遇到并已解决的问题，供维护者和二次开发者参考。

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| 平台无关 | 业务规则写在 `AGENTS.md` / `SKILL.md`，脚本只做 I/O；更换 Agent 平台无需改代码 |
| 资金安全优先 | 发现层只读；写操作只经过官方 CLI 的预演流程；默认拒绝一切非 0 元操作 |
| 可审计 | 每次决策与交易写入 `seen.json` 与 `events.jsonl`；汇报附 BscScan 链接 |
| 容错 | RPC 多节点轮换、会话多次复查、交易结果按哈希核对而非重发 |

## 2. 分层

### 2.1 发现层（只读）

| 来源 | 识别依据 |
|---|---|
| 链上新合约 | 字节码引用 Agent ID 注册表 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F`；EIP-1967 / Beacon 代理追溯到实现合约 |
| 链上热度 | 同一合约 3 分钟内被 ≥12 个钱包小额调用 |
| 铸造事件 | 同一 NFT / 代币 30 分钟内铸给 ≥6 个不同地址（可覆盖 CREATE2、工厂部署、EIP-7702 等情形） |
| 付费分档 fair mint | `Minted` 事件全链扫描，读取单价、进度、开池状态；预建空池须储备 > 0 才判定为已开池 |
| 项目官网 | `/skill.md`、`/llms.txt`、`/agent.md`、`/deployment.json`、`/api/state`；首页、脚本及一层 import（如 `config.mjs`）中的合约地址 |
| 社区与平台 | 公开 TG 频道、Four.meme OpenFour Agent ID 专区、Gang.fun、Flap Agent Curve；进度单次跳升 ≥15 个百分点单独标记 |
| 项目目录 | 服务端签名、客户端验签，拒收被篡改或超过 24 小时的数据；遵守退避，最短 5 分钟拉取一次 |

### 2.2 核验层（Agent）

1. **来源核对**：只采信官方渠道公布的合约；仅链上发现的项目在汇报中注明。
2. **合约核对**：Sourcify 验证源码与 ABI；`riskcheck.py` 检查权限与貔貅；可选 Clawby 流动性与安全数据。
3. **机制核对**：按 `monitor/mint-patterns.json` 的 14 类机制逐项回答（资格、免费范围、每号限额、首张与后续报价、随机数、PoW、签名结算、生命周期等）。
4. **防钓鱼过滤**：重复或黑名单部署者、同字节码批量部署、新钱包部署、虚假进度、名称蹭热度、宣传与合约不符等。

### 2.3 决策与执行

决策分三档：**自动执行**（严格 0 元且预演干净）、**简报待确认**（付费、需签名或存在不确定项）、**避开**（命中风险或投毒迹象）。

执行流程固定为：`baw contract-call preview` → 检查预演结果 → `baw contract-call execute --requestId <id>` → 以 receipt 铸造事件或 `balanceOf` / `ownerOf` 核对到账。

## 3. 关键原则

- **免费 ≠ 无条件**：持有 Agent ID 不代表仍有免费额度；需分清按地址、按身份还是按 tokenId 计数。
- **免费 ≠ 零成本**：gas、预言机费、资格资产另计；首张免费不代表后续免费，动态报价需分别读取。
- **value = 0 ≠ 无扣款**：可能通过 ERC-20 扣费；报价读取失败不等于价格为 0。
- **提交 ≠ 到账**：第一步成功不代表活动完成，以链上状态为准。
- **不继承旧结论**：合约、选择器、价格、开放状态与资格承诺都需重新读取。

## 4. 重放他人交易的约束

| 情形 | 处理 |
|---|---|
| transfer / approve / NFT 转移类调用 | 一律不重放 |
| calldata 含他人地址 | 替换为本地址；不成功再尝试零地址；仍失败则放弃 |
| 含签名、Merkle proof、PoW nonce、时间戳 | 不重放，从官网或合约获取本地址专属参数 |

## 5. 钱包会话

| 问题 | 原因 | 解决方案 |
|---|---|---|
| 运行环境变化后「假掉线」 | CLI 默认以网卡信息加密会话 | 每账号固定 `instance_id`，由 `baw-wrapper.sh` 注入 |
| 偶发网络错误被误判掉线 | 单次检查不可靠 | `safe_session.sh check` 连续 3 次失败才判定 `UNCONNECTED` |
| 重复登录挤掉现有会话 | 多处发起配对 | 只保留 `safe_session.sh signin` 一个入口，存在未过期配对码时不再生成 |

## 6. 特殊机制

- **PoW 型 Mint**：每个钱包的 challenge 不同，不能复用他人 nonce。先读合约确认哈希拼接方式，本地计算后用合约 `verify` 校验，再预演；按难度估算期望耗时，过高则放弃。
- **解题 / 面试 / 签名型 Mint**：自动走 challenge → 解题 → 提交 → 获取项目方签给本地址的 mint 授权 → 预演 → 执行；登录只接受 EIP-712 签名。无法自动完成时必须单独通知用户，不得静默跳过。
- **分阶段开放**：读取合约或官网的开放时间，提前创建一次性任务，由 `phase_mint.py` 准点执行。

## 7. 运维

| 问题 | 解决方案 |
|---|---|
| 公共 RPC 限流（429） | `rpcpool.py` 维护 11 个公共节点，失败自动切换并冷却 60 秒；多账号查询使用批量请求 |
| Gas 不足导致免费 Mint 失败 | `gas_topup.py` 在 BNB 低于阈值时用 USDT 兑换，受每日次数上限约束 |
| 第三方接口频率限制 | `clawby.sh` 串行调用并保持最小间隔 |
| 依赖与技能过期 | `update_skills.sh` 每日更新，自检失败自动回滚 |
| 记录重复 | `seen.json` 按合约地址（小写）去重，已存在则更新原记录 |

## 8. 可选能力与默认关闭项

以下能力仅在用户明确书面授权后启用，默认关闭：

- 指定时段内的小额自动付费进场及止盈止损（单笔与每日额度上限由用户设定）；
- 任何形式的授权（approve）操作。

以下能力不提供：无限授权、permit 类签名、需要登录的私有信号源。
