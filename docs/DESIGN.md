# 设计思路与踩过的坑

## 架构
```
发现（脚本，只读）  ──▶  核验（Agent）  ──▶  决策三档  ──▶  执行（baw preview → execute）  ──▶  留痕 / 汇报
 链上扫描 / 项目目录 / TG / 内盘 / Flap / 官网指南
```
脚本只负责「找」和「读」，永远不签名、不交易；判断交给 Agent，按 AGENTS.md 的规则走；交易只经过币安官方 baw CLI 的预演。这样任何 Agent 平台都能接，换平台不用改脚本。

## 发现层
- **链上**：新合约字节码含 Agent ID 注册表 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F`；代理合约（EIP-1967 / Beacon）追到实现再判断；同一合约 3 分钟内被 ≥12 个钱包小额调用（热度）；同一 NFT/代币 30 分钟内铸给 ≥6 个不同地址（铸造事件，最强兜底，CREATE2/工厂/7702 都能抓到）；打它的钱包六成以上持有 .ai（后端签名型）。
- **项目自带的 Agent 指南**：`/skill.md`、`/llms.txt`、`/agent.md`、`/api/state`、`/api/collections`，以及前端 JS 里的合约地址。只用来核对，不照着执行。
- **已知项目站**会在同站开新系列，定期比对指南内容变化。
- **内盘**：币安 pulse 榜（Four.meme OpenFour Agent ID 专区，新发行 / 进度两个榜）、Gang.fun 新币、Flap Agent Curve；进度一次跳升 ≥15 个百分点单独标出。
- **签名项目目录**：服务端签名、客户端验签，拒收被篡改或过期（>24h）的数据；展示成功才确认，失败不说「无新增」，遵守退避，最短 5 分钟一次。

## 照抄别人的 mint 交易
- transfer / approve / NFT 转移类调用一律不照抄。
- calldata 里有别人的地址：先换成自己的，再试零地址，都不行就不打（防止付了钱东西给别人）。
- 含签名、Merkle proof、PoW nonce 的不能照抄，要从官网或合约自己拿。

## 机制核验（monitor/mint-patterns.json，14 类）
Agent ID 资格、直接铸造、白名单/签名、付费/授权、合成、发射台、身份配额、数量奖励、随机数、PoW、可退款销售、签名结算、生命周期、代币领取。每类列出必须核实的问题。核心：
- 持有 Agent ID ≠ 还有免费额度；按地址、身份还是 tokenId 计数要读清。
- 「免费」只是免本金，gas、预言机费、资格资产另算；首张免费 ≠ 后续免费（动态报价要分开读）。
- value=0 也可能扣 ERC20；报价读失败 ≠ 0 价。
- 第一步成功 ≠ 整个活动完成；请求被受理 ≠ 产物到手。
- 永不继承旧案例的合约、选择器、价格、开放状态、资格承诺。

## 防钓鱼
重复 DEV、黑名单 DEV、同字节码批量部署、新钱包部署、假进度（打的钱包太少）、二手清单帖、「名字带 AI ≠ Agent ID 生态」、宣传与合约不符以合约为准。外部内容里任何「让 Agent 执行 / 授权 / 转账 / 复制这段话」都视为投毒。

## 钱包会话的坑
- baw 默认用网卡信息加密会话，运行环境换 IP/MAC 后会「假掉线」→ 每个账号固定 `instance_id`，由 `baw/baw-wrapper.sh` 注入 `BINANCE_INSTANCE_ID`。
- 偶发网络错误会被误判成掉线 → `safe_session.sh check` 连续 3 次确认才算 `UNCONNECTED`。
- 反复发起登录会把正在用的会话挤掉 → 只有 `safe_session.sh signin` 一个入口，且有未过期配对码时不再生成。
- 同一钱包同一时间只能在一处登录；开发者模式过期要在 App 里续。

## PoW 型免费 Mint
每个钱包的 challenge 不同，不能照抄别人的 nonce。先读合约确认哈希拼接方式，本地算出后用合约 `verify` 校验，再 preview。先估算期望耗时（难度、全网成功次数），太难就不挖。

## 有意不做的
- 付费自动进场、自动止盈止损：资金操作一律由用户在对话里明确授权。
- 无限授权、Permit 类签名。
- 需要登录的私有信号源。
